📝 Упражнение 1: Переписать команду в делегирование

После модуля 01: юнит 2 — Четыре сдвига.

Цель: Научиться переходить от команд к описанию результата.

Задание:

У тебя есть вот такой "промпт" (команда):

Установи npm
Создай package.json
Установи React
Установи Tailwind
Создай папку src
Создай App.tsx

Что делать:

  1. Переписать это в делегирование (описание результата)
  2. Сохрани в my-experiments/exercise-1-delegation.md

Пример результата:

# Exercise 1: Delegation

## Вход (ЧТО БЫЛО):
Команды по шагам...

## Выход (ЧТО СТАЛО):
Я хочу создать React приложение для [НАЗНАЧЕНИЕ].

Требования:
- TypeScript поддержка
- Tailwind CSS
- Структура: компоненты в src/

Результат: приложение, которое запускается на localhost:3000

Проверка:

  • Переписал "Установи X" в "Мне нужно Y"?
  • Добавил цель и контекст?
  • Описал, как узнать, что это работает?

🔄 Упражнение 2: Экспериментирование с промптами

После модуля 04: юнит 2 — Формула спецификации.

Цель: Научиться итерировать и сравнивать результаты.

Задание:

Создай компонент кнопки. Но сделай это в 3 итерациях:

Попытка 1: Минимальный промпт

Создай React компонент кнопки.

Попытка 2: С деталями

Создай React компонент кнопки.
- Поддерживает primary/secondary варианты
- На hover меняется цвет
- Disabled состояние

Попытка 3: Полный промпт

Создай React компонент Button для дизайн-системы.

Требования:
- Варианты: primary (синяя), secondary (серая), danger (красная)
- Размеры: sm, md, lg
- Состояния: normal, hover, active, disabled
- На hover: scale 1.05
- Disabled: opacity 0.5
- TypeScript, с типизацией props

Результат: файл Button.tsx с примерами использования

Что делать:

  1. Запусти Claude Code в папке my-experiments/button-exercise
  2. Попробуй все 3 варианта промпта
  3. Сравни результаты
  4. Сохрани в exercise-2-iterations.md

Сохранить:

# Exercise 2: Iterations

## Попытка 1: Минимальный промпт
[Результат от Claude Code]

## Попытка 2: С деталями
[Результат от Claude Code]

## Попытка 3: Полный промпт
[Результат от Claude Code]

## Анализ:
- Какой вариант был самый эффективный?
- Сколько было итераций уточнения?
- Какие детали были самыми важными?

Проверка:

  • Пробовал 3 варианта?
  • Сравнил результаты?
  • Выписал, какой вариант был лучше и почему?

📋 Упражнение 3: Структурирование контекста

После модулей 02 и 05: юнит 3 — Первый проект и юнит 4 — Настрой свою память. Дублирующую практику делай в этих юнитах, а здесь зафиксируй только свой результат.

Цель: Научиться создавать хорошие AGENTS.md, TODO.md и STATE.md.

Задание:

Возьми существующий проект (любой, который есть на диске). Создай для него:

  1. AGENTS.md - полный контекст и правила проекта (+ CLAUDE.md со строкой @AGENTS.md для Claude Code)
  2. TODO.md - текущие задачи
  3. STATE.md - где остановились

Структура AGENTS.md:

# AGENTS.md

## Моя роль
[Кто ты для этого проекта]

## Проект
[Что это, зачем нужно]

## Стек
[Технологии и версии]

## Структура
[Папки и их назначение]

## Как запустить
[Команды для старта]

## Текущее состояние
[Что работает, что нет]

## Когда вызывать Claude Code
[Для каких задач]

Что делать:

cd [твой-проект]
touch AGENTS.md TODO.md STATE.md
echo '@AGENTS.md' > CLAUDE.md

# Заполни каждый файл
# Сохрани результаты в git
git add AGENTS.md CLAUDE.md TODO.md STATE.md
git commit -m "Add agent context files"

Проверка:

  • AGENTS.md содержит всю необходимую информацию и твой стиль работы?
  • TODO.md расставлены приоритеты?
  • STATE.md говорит, что делать дальше?
  • Файлы добавлены в git?

🎨 Упражнение 9: Vibe Coding — MVP за вечер

После модуля 03: юнит 5 — План миграции твоего workflow.

Это упражнение выполняется в браузере.

Цель: Пройти полный цикл от идеи до рабочего продукта используя AI-стек.

Что такое Vibe Coding

Это подход, при котором ты фокусируешься на продуктовом мышлении, а не на технической реализации. AI-инструменты покрывают код, ты — задаёшь направление.

Стек: Perplexity → Grok → Lovable → Supabase

ИнструментРольЧто делает
PerplexityResearchАнализ рынка, конкуренты, целевая аудитория
GrokPlanningПошаговые инструкции, генерация промптов
Lovable / bolt.newFrontendПолный UI по промпту (React + Tailwind)
SupabaseBackendБаза данных, авторизация, API без кода

Задание: Построй инструмент для себя

Выбери задачу из своей жизни (не абстрактную!). Примеры:

  • Трекер привычек
  • Дашборд для своего проекта
  • Простая CRM для клиентов
  • Генератор отчётов

Шаги:

Шаг 1: Research (Perplexity, 20 мин)

Запрос: "Что уже существует в категории [ТВОЯ ИДЕЯ]?
Топ-5 конкурентов, их слабые стороны, незакрытые потребности аудитории."

Шаг 2: Plan (Grok, 15 мин)

Запрос: "Я хочу построить [ИДЕЯ]. Дай пошаговый план MVP.
Составь промпт для Lovable/bolt.new — что именно ему написать."

Шаг 3: Build Frontend (Lovable / bolt.new, 30 мин)

Вставь промпт из шага 2. Итерируй — объясняй на языке дизайна:
"Сделай кнопку крупнее", "Добавь таблицу с данными", "Добавь боковое меню"

Шаг 4: Connect Backend (Supabase, 20 мин)

  • Создай проект на supabase.com
  • Lovable умеет подключиться напрямую через /integrate supabase
  • Укажи таблицы — и данные сохраняются автоматически

🎁 Трек (опционально): Упакуй свою экспертизу в продукт

«Усиливай свой голос, не заменяй его.»

Этот трек — для коучей, экспертов, практиков, целителей: тех, у кого уже есть дар, и кто хочет, чтобы он дошёл до большего числа людей. Это не «машина для денег» и не воронка с фейк-дедлайнами. Это про то, чтобы собрать и поделиться тем, что ты уже умеешь — твоим голосом, а AI берёт на себя оформление, а не подмену. Делай по одному шагу, сохраняй результат в my-experiments/.

Шаг 1. Назови свой дар

Цель: одним абзацем, без оффер-копи.

Ответь честно: что ты даёшь людям, кому именно, какой сдвиг у них происходит. Не «продающий текст» — простая правда. Сохрани в my-experiments/offer-1-gift.md.

Шаг 2. Найди повторяющийся промпт

Цель: найти ядро будущего продукта.

С каким вопросом или болью к тебе приходят снова и снова? Этот повторяющийся промпт — и есть то, что стоит упаковать первым. Выпиши три таких промпта и выбери один. Сохрани в my-experiments/offer-2-core.md.

Шаг 3. Спроектируй с AI-агентом

Цель: структура, где ведёшь ты.

Возьми Skill из модуля 4 (промпт-инжиниринг) и попроси агента помочь разложить твой ответ на промпт в понятную структуру — программу, гайд или мини-курс. Ты держишь смысл и голос; агент оформляет. Если он начинает писать за тебя «как надо продавать» — останови: тебе нужна структура, не манипуляция. Сохрани черновик в my-experiments/offer-3-design.md.

Шаг 4. Собери первую версию

Цель: маленький честный объём.

Собери vibe-кодингом первую рабочую версию — лендинг, гайд в PDF, или одну страницу с твоим оффером. Не «идеально» и не «на всю программу» — ровно столько, чтобы реальный человек мог это получить и попробовать. Сохрани ссылку/файл в my-experiments/offer-4-build.md.

Шаг 5. Поделись, не впаривай

Цель: пригласить, а не надавить.

Покажи это нескольким людям, которым оно действительно полезно. Без scarcity, без обратных отсчётов, без «осталось 2 места». Просто: «я собрал вот это, думаю, тебе пригодится». Собери честную обратную связь и вернись к шагу 3 — это цикл, а не финиш. Запиши, что узнал, в my-experiments/offer-5-share.md.

Готово. Ты не построил «воронку» — ты дал своему дару дойти до людей, оставшись собой.

🔧 Трек (опционально): Задокументируй и автоматизируй свою практику

«Сними рутину с рук — чтобы осталось время на человеческое.»

Этот трек — для тех, у кого есть повторяющаяся практика: коуч, мастер, фрилансер, маленькая команда. Цель — не «заменить себя» и не построить контент-конвейер, а снять с себя нудную повторяющуюся часть, чтобы осталось время на то, что умеешь только ты. AI берёт на себя писанину и рутину; суждение и живой контакт остаются за тобой. Делай по одному шагу, сохраняй результат в my-experiments/.

Шаг 1. Выбери одну повторяющуюся задачу

Цель: одна задача, не весь бизнес.

Выбери из меню одну вещь, которую ты делаешь снова и снова:

  • онбординг нового клиента
  • еженедельный отчёт или сводка
  • ответы на частые вопросы
  • подготовка и публикация поста
  • выставление счёта / напоминание об оплате

Возьми ровно одну — самую надоевшую. Запиши выбор в my-experiments/sop-1-pick.md.

Шаг 2. Расскажи её вслух — собери SOP с AI

Цель: превратить «то, что в голове» в понятные шаги.

Опиши агенту, как ты делаешь эту задачу — своими словами, как рассказал бы коллеге. Попроси разложить это в простой SOP: шаги, входы, что считается «готово». Ты правишь и держишь смысл; агент оформляет. Сохрани SOP в my-experiments/sop-2-document.md.

Шаг 3. Найди, что можно отдать машине

Цель: отделить рутину от суждения.

Пройдись по SOP и отметь: где механическая рутина (формат, копипаст, шаблон), а где нужно твоё суждение или живой контакт. Автоматизируй рутину — человеческое оставь человеку. Выпиши, что именно отдаёшь машине, в my-experiments/sop-3-automate.md.

Шаг 4. Собери одну маленькую автоматизацию

Цель: один рабочий кусочек, не вся сисмодуль.

Собери vibe-кодингом или промптом одну автоматизацию из шага 3 — шаблон письма, скрипт-заготовку, чек-лист-генератор. Не «весь процесс», а один честный кусок, который реально экономит время. Проверь на настоящей задаче. Сохрани в my-experiments/sop-4-build.md.

Шаг 5. Оставь это живым

Цель: не свалить в архив.

Используй SOP и автоматизацию на следующей реальной задаче и поправь то, что не сошлось. Это не «готовый продукт», а живой инструмент, который растёт с практикой. Запиши, что улучшил, в my-experiments/sop-5-live.md.

Готово. Ты не заменил себя — ты убрал рутину с дороги, чтобы делать то, ради чего тебя зовут.

🔎 Трек (опционально): Поиск с AI

«Перестань вспоминать операторы поиска — научись исследовать вместе с AI.»

Раньше «уметь искать» значило помнить операторы Google. Теперь — уметь вести исследование вместе с AI и проверять то, что он выдаёт. AI ускоряет поиск, но может уверенно ошибаться и выдумывать источники — поэтому правило трека простое: не верь без источника. Делай по одному шагу, сохраняй результат в my-experiments/.

Шаг 1. Выбери настоящий вопрос

Цель: реальный вопрос, а не «потренироваться».

Возьми вопрос, который ты бы и так загуглил(а) на этой неделе — рабочий, бытовой, любой настоящий. Сформулируй его одним предложением, как задал(а) бы живому эксперту. Запиши вопрос в my-experiments/research-1-question.md.

Шаг 2. Спроси AI-поисковик и веди цикл уточнений

Цель: не первый ответ, а разговор.

Задай вопрос AI-поисковику — Perplexity, поиск в ChatGPT или Gemini. Не останавливайся на первом ответе: уточняй, переспрашивай, проси сузить или копнуть глубже. Хороший research — это цикл, а не один промпт. Сохрани вопросы и ключевые ответы в my-experiments/research-2-loop.md.

Шаг 3. Включи режим deep research

Цель: глубина там, где она важна.

Для вопроса, который правда важен, включи режим глубокого исследования (deep research в ChatGPT, Gemini или Perplexity). Дай ему время пройтись вширь и собрать отчёт. Сохрани, что он нашёл — вместе со списком источников — в my-experiments/research-3-deep.md.

Шаг 4. Заземлись и ПРОВЕРЬ источники

Цель: отделить правду от уверенного вымысла.

Открой настоящие источники, на которые ссылается AI, и сверь утверждения. Ссылка не открывается, источник не подтверждает мысль или его вовсе нет — вычеркни этот кусок. Это сердце трека: не верь без источника, даже когда звучит убедительно. Отметь, что подтвердилось, а что нет, в my-experiments/research-4-verify.md.

Шаг 5. Синтез: веб-поиск × AI

Цель: свой обоснованный ответ, а не чужой пересказ.

Соедини обычный веб-поиск с AI-синтезом: где-то быстрее открыть пару живых страниц самому, где-то — дать AI собрать картину. Собери из проверенного свой короткий ответ на исходный вопрос и отметь, где AI ошибался. Сохрани итог в my-experiments/research-5-synthesis.md.

Готово. Теперь ты не вспоминаешь операторы поиска — ты ведёшь исследование с AI и держишь источники под рукой.
