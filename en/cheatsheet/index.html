Claude Code Cheat Sheet

A quick reference for working with Claude Code and prompt engineering. Verified on Claude Code 2.1.289.

💡 Your system is detected automatically — Mac- and Windows-specific commands are filtered to it. Switch above if you need the other.

🖥️ CLI: launch and flags

claude                          # Interactive mode
claude "request"                # Launch with an initial request
claude -p 'request'             # Pipe mode: response to stdout and exit
claude -c                       # Resume the last session
claude -r <id>                  # Resume session by ID
claude update                   # Update Claude Code

# Useful flags
--model <model>                 # Specify model at launch
--permission-mode plan          # Launch in read-only mode
--worktree / -w                 # Isolated git worktree
--autocompact <auto|tokens>      # Auto-compaction mode; -n = --name
--add-dir <path>                # Add a folder to context
--output-format json|text|stream-json
--max-budget-usd <N>            # Session budget in dollars
--bare                          # Minimal mode: no hooks, LSP, plugin sync, or auto-memory

# Pipe mode — handy for scripts:
cat error.log | claude -p 'explain the error'

📋 Session management

/clear                  # Full context wipe
/compact [topic]        # Compress context, keep the essentials
/context                # Show context fill
/resume                 # List recent sessions to resume
/rename <name>          # Rename the session (handy for /resume)
/branch                 # Create a session branch
/cost                   # Current session cost ($, tokens)
/diff                   # All file changes this session
/copy                   # Copy the last response
/export                 # Export the conversation to Markdown

Decision tree /clear vs /compact:

SituationCommand
Context is full (>80%) or the task changed/compact
Context <70% and the task is the sameContinue

💡 CLAUDE.md (and the @AGENTS.md it imports) is auto-reloaded after /compact and auto-compact — instructions aren't lost.

⚙️ Settings

/config                         # Open settings.json in the editor
/model <model>                  # Switch model in the session
/fast                           # Fast mode: same model, faster output
/effort low|medium|high         # Analysis depth
/permissions                    # View and configure permissions
/vim                            # Enable vim editing mode
/theme                          # Change color theme

💡 Reasoning depth. Maximum on planning and verification, one level lower on implementation. For LangChain this "sandwich" scored 66.5% on Terminal Bench 2.0, while "maximum everywhere" scored 53.9%: the agent ran out of time.

🌀 Ultrathink

Activate deep thinking — trigger words in the prompt:

think → think hard → think harder → ultrathink

Or the Alt+T key. Useful for: architectural decisions, tough bugs, ambiguous specs.

Pattern Plan → Normal → Auto:

1. Plan mode   → recon only, no changes
2. Normal mode → implementation with confirmation
3. Auto-accept → routine without confirmation (Shift+Tab)

# 1. Create and enter a project
mkdir my-project && cd my-project

# 2. Create memory files

echo '@AGENTS.md' > CLAUDE.md

# 3. Fill in AGENTS.md with the agent

📋 Structure of a good prompt

## Role
You are — [description + expertise]

## Task
[Specific task]

## Inputs
[Input data]

## Expected output
[Expected result]

## Constraints
[Constraints]

Mnemonic CTID — see 04/u2: Context · Task · Instructions · Data.

🎯 Delegation matrix

✅ Delegate:

  • Routine operations (formatting, conversion)
  • First drafts (text, code)
  • Information lookup
  • Tests
  • Documentation

🧠 Decide yourself:

  • Architecture
  • Final quality assessment
  • Strategic decisions
  • Ethical questions
  • Ambiguous tasks

🔁 Process: plan, check, review

  • Plan in stages, each stage with its own check. Not "do everything" but "stage 1 → test → stage 2 → test". When something breaks, you see where.
  • Review with fresh eyes. Hand finished work to a new session or another model (Claude ↔ Codex) for review. The author misses their own mistakes; a fresh context finds them.
  • Let it interview you first. Before the work starts, ask the agent to interview you: in Claude Code that is the AskUserQuestion tool, with any other agent say "ask me 5 questions before you begin". Answering questions is cheaper than redoing work.
  • One subagent, one skill. Not a "general QA engineer" but "checks DB migrations" or "reads Chrome logs". A narrow role with a concrete tool works; a broad one smears out.
  • A set of your own examples. 10–20 cases with the expected result — rerun them after every change to the prompt or the code.
  • Backend first. Make sure the pipeline collects the right data before building the screen on top of it: a beautiful interface over an empty database is the most expensive beginner's mistake.
  • Ask for presets. Anything you run more than twice should become a reusable configuration, with changeable parameters moved into settings instead of hard-coded.
  • Project longer than one evening? Take a ready-made process: Superpowers or Spec Kit (links in "Materials").

📄 Required project files

AGENTS.md

One file of project context and rules for any agent: Codex, Cursor, Copilot, Antigravity and Hermes read it on their own.

Where to put it:

  • ./AGENTS.md — project (committed to git)
  • ./CLAUDE.md — one line, @AGENTS.md: that is how Claude Code reads it
  • ~/.claude/CLAUDE.md — personal (all projects, Claude Code only)

Limit: ~200 lines (important for context)

Minimal structure:

# AGENTS.md
## My role
## Project
## Stack
## How to run
## Rules
## What to avoid

/init in Claude Code generates a CLAUDE.md from an existing project. Move what's useful into AGENTS.md and leave @AGENTS.md in CLAUDE.md. Treat the generated file as a draft: an ETH Zurich study (2026) found that context files don't raise agent success on average, add more than 20% to the cost, and repository overviews don't help. Keep what the agent can't find out on its own: non-standard rules, check commands, bans.

TODO.md

# Tasks
## 🔴 CRITICAL
## 🟡 IMPORTANT
## 🟢 LATER
## ⏸️ BLOCKED
## ✅ DONE

STATE.md

# Project state
## Where we are
## Done
## Blockers
## Next step

⚠️ Common mistakes

MistakeFix
Context overflowingOnly feed relevant files
Agent asks everythingAdd the info to AGENTS.md
Wrong resultSpecify what exactly is off, iterate
DistractorsRemove extra files from context
"Lost in the Middle"Important stuff at the start or end, not middle

💡 Quick tips

What to use when

For analyzing a codebase:

Ask the agent: “explore the codebase” (the Explore subagent)

For planning a big piece of work:

/plan

For quickly adding info:

/btw Update the context: [info]

For exploring a specific file:

Ask the agent: “explore the codebase and find the files responsible for [X]” (the Explore subagent)

🎯 Prompt quality check

Before sending:

  • Role is clear?
  • Task is specific?
  • Data is complete?
  • Output is defined?
  • Constraints are clear?
  • No distractors?
  • Important stuff at the start/end?

🔢 Tokens

📖 What a token, context window, temperature, prompt vs context and an agent are — in plain words in the unit "ABC: six words before you start".

1 token ≈ 4 characters
1000 tokens ≈ 750 words

Cost:
- Input token = cheaper
- Output token = pricier (2–3×)

Optimize:
- Compress context
- Strip the extra
- Structure your data

🌍 Prompt examples

Backend request

## Role
You are a seasoned backend developer with 10 years of experience.
You know Node.js, PostgreSQL, microservices.

## Task
Create a REST API endpoint for fetching the user list.

## Input
- Fields needed: id, name, email, created_at
- Pagination support (page, limit)
- Filtering by email

## Output
- Express route handler
- TypeScript types
- Example curl requests

## Constraints
- Use a PostgreSQL query builder (knex.js)
- Max 50 lines of code
- Add validation for query parameters

Frontend request

## Role
You are a frontend developer, an accessibility specialist.

## Task
Create a React component for a product filter.

## Input
- Filters: category (checkbox), price (range), rating (radio)
- Sample data in data.json

## Output
- React component Filter.tsx
- Tailwind CSS styles
- WCAG AA accessibility

## Constraints
- TypeScript
- No UI libraries (pure CSS)
- Keyboard navigation (Tab, Enter, Escape)

Research request

## Role
You are a UX researcher experienced in user interviews.

## Task
Analyze interview.txt and find the main user pain points.

## Input
- File interview.txt with the interview recording

## Output
- Top 5 user problems
- For each: description, quote, possible solution

## Constraints
- Max 1 page
- Direct quotes from the interview only
- Prioritize by frequency of mentions

📊 Result check

# Result is good if:
- ✅ Code runs without fixes
- ✅ Structure is clear

- ✅ Performance is acceptable

# Result is bad if:
